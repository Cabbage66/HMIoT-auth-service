# 阶段8：信任评估结果接入与风险阻断联动（实施计划与实现结果）

## 阶段目标

完成信任评估结果接入、风险阻断状态持久化、访问链路阻断联动与解除闭环。

## 实施计划（详细）

1. 信任评估结果接入
- 调用 `POST /api/v1/trust-assessments/check` 获取 trusted/failReason 等结果。

2. 风险阻断状态模型
- 本地持久化阻断状态：`blocked`、`reason`、`updatedAt`。

3. 访问链路联动
- 访问前优先检查阻断状态。
- 若阻断中，直接拒绝并输出二次认证/解除提示。

4. 信任中心页面
- 手动触发信任评估。
- 展示阻断状态与原因。
- 支持手动解除阻断。

5. 自动联动
- 在终端采集 Worker 中同步触发信任评估并更新阻断状态。

### 补充实现结果
- Android：
  - `feature/trust/domain/TrustGuardRepository.kt`：执行信任评估前强制 `collectAndQueue + flushQueue`，再调用 `/trust-assessments/check`。
  - `core/storage/datastore/AppPreferenceStore.kt`：`TrustGuardState` 增加 `trustScore/trustLevel/riskLevel/decision/requestId/requestLogPath/resultLogPath` 持久化字段。
  - `feature/terminal/data/TerminalMonitorApi.kt`：`TrustCheckResponse` 增加 `requestLogPath/resultLogPath` 字段映射。
  - `MainActivity.kt` + `InternalSystemPureUi.kt`：将信任分、等级、风险结果和日志路径接入“信任监控仪表盘”展示（保持既定 UI 样式）。
- Backend：
  - 新增 `TrustAssessmentFileLogService`：将评估请求、评估结果写入 `runtime/trust-assessment-logs/{yyyyMMdd}` 文件。
  - `TrustAssessmentService`：评估调用前后分别落盘请求/结果日志；将日志路径写入结果 `rawResponse`；`/trust-assessments/check` 回传 `requestLogPath/resultLogPath`。
  - `TrustAssessmentCheckResponse`：扩展日志路径返回字段。
