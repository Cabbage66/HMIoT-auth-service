**目标**

修复登录后“系统安全情况/安全状态”点击闪退问题，按《2) 采集了哪些“系统安全信息”》中的字段完成真实采集、分组展示、服务端日志化上报与信任评估联动。

**实施规划**

1. 采集项核对与补齐
   - 系统完整性：Root、Bootloader、OS 签名可信状态。
   - 运行环境风险：模拟器、ADB、Hook 风险。
   - 系统基线：API Level、安全补丁、系统版本。
   - 网络安全：连接类型、VPN、Wi-Fi 加密状态。
   - 应用风险：高风险应用、应用签名、未知来源安装。
   - 设备身份与上下文：设备标识、设备 ID、Android ID、应用版本、设备指纹、客户端 IP、位置。
   - 生物能力：指纹、人脸、声纹、安全硬件、本地人脸比对能力。
2. 链路接入
   - 登录成功后采集一次，写本机文件日志，排队上报服务端，再触发信任评估。
   - 每次系统内应用访问前重新采集、上报、评估，再执行本地策略与 SSO 访问。
   - 安全页手动检测与信任评估按钮复用同一流程，避免重复采集和重复排队。
3. 日志方式
   - 客户端写应用私有目录 JSONL 文件：`files/security-event-logs/terminal-security-日期.jsonl`。
   - 服务端继续使用已有终端事件文件日志与信任评估请求/结果文件日志。
4. UI 与提示
   - 沿用当前系统既定 UI 样式，不新增独立设计体系。
   - 安全页按 7 个模块展示字段，未知或系统未开放的采集项明确显示原因。
   - 提示框只展示主要成功/失败信息，去除 traceId、异常类名等无关内容。

**实现结果**

1. 采集实现
   - `TerminalStatusCollector` 支持 `triggerScene` 与 `appCode`，并补齐 Bootloader、高风险应用、Wi-Fi 安全状态等真实检测。
   - 保留定位权限限制：未授权时页面显示“未授权/未采集”，不伪造位置。
2. 日志与上报
   - 新增 `TerminalSecurityFileLogger`，每次采集写入客户端本机 JSONL 条目日志。
   - `TerminalMonitorRepository.collectAndQueue()` 写本机日志后再进入待上报队列。
   - `TrustGuardRepository.evaluateAndUpdate()` 统一负责采集、上报、信任评估与本地信任状态更新。
3. 访问与登录触发
   - `MainActivity` 登录后自动执行 `LOGIN` 场景安全采集与评估。
   - 应用访问前执行 `APP_ACCESS` 场景安全采集与评估，并将应用编码写入采集上下文。
   - 安全页检测执行 `SECURITY_PAGE`，手动信任评估执行 `MANUAL_TRUST_CHECK`。
4. 页面展示
   - `InternalSystemPureUi` 新增安全详情分组数据结构。
   - 安全页展示：系统完整性、运行环境风险、系统基线、网络安全、应用风险、设备身份与上下文、生物能力。
   - 首页“当前系统安全情况”显示实际检测模块数量，点击软件/硬件状态不会因异常直接闪退。
5. 稳定性
   - 安全检测流程增加异常兜底，失败时只展示主要失败原因。
   - 定时采集与上线检查去掉重复采集路径，统一走信任评估入口。

**补充实现：安全状态二级页与深色模式**

1. 安全状态页面结构
   - 一级页保持当前系统样式，只展示“软件状态”和“硬件状态”两个分类入口。
   - 点击“软件状态”进入二级页，展示：系统完整性、运行环境风险、系统基线、网络安全、应用风险。
   - 点击“硬件状态”进入二级页，展示：设备身份与上下文、生物能力。
   - 二级页顶部提供返回入口，并保留“重新检测”操作。
2. 展示逻辑
   - 采集内容不再全部堆在一级安全页。
   - 每个二级模块展示模块状态、状态徽标和对应字段键值。
   - 未授权/系统未开放的数据按真实状态展示，不伪造。
3. 日志与信任评估解耦
   - 客户端采集后先写本机 JSONL 日志并排队上报。
   - 固定本机日志文件：`/data/user/0/com.hmiot.app/files/security-event-logs/terminal-security.jsonl`。
   - 服务端终端事件日志目录：`backend/runtime/terminal-event-logs`，按日期和终端编号归档。
   - 信任评估失败时，页面保留采集条目展示，并提示“安全信息已采集并展示，日志已记录；信任评估暂未完成”，不再让用户误解为采集失败。
4. UEBA 模型端口兜底
   - 后端 `UebaIntegrationClient` 在 HTTP 模型端口不可用、返回错误或响应不完整时自动使用 mock 评估结果。
   - Java 后端终端会输出：`[HMIoT][UEBA模拟] ... 已使用模拟评估结果 ...`。
5. 深色模式
   - 登录后的系统页面新增语义色 token，背景、面板、二级卡片、文字、分割线、提示框、底部导航均支持系统深色模式。
   - 二级详情页按移动端可触达、清晰返回路径和明暗对比规则实现。
6. 条目展示修正
   - 软件/硬件详情页每个字段独立成条目行，包含状态点、字段名、采集值。
   - 点击软件/硬件分类入口时会先触发一次采集，保证进入二级页后能看到最新设备采集内容。
   - “重新检测”只负责采集、展示、写日志、同步上报；信任评估作为附加结果返回，不阻塞条目展示。
