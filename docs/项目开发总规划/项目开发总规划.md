# 多网融合人机物电子认证服务项目开发总规划

## 一、规划目标

本规划依据《项目需求（整理版）》和《测试方案_回忆版》制定，目标是建设一个可演示、可扩展、可审计的正规系统。系统需覆盖用户管理、证书/USB 认证、终端绑定、动态生物绑定、物联网设备绑定、单点登录、跨系统互认、跨域访问、信任评估和审计日志等能力。

开发策略采用“先主链路、再扩展能力、最后联调加固”的方式推进。每一阶段均形成可运行版本，避免功能堆叠后集中联调失控。

## 二、总体系统范围

### 1. 系统组成

* 前端管理端与网页客户端：统一放在 `frontend`，用于管理员操作、用户网页登录、应用访问模拟。
* 服务端：放在 `backend`，承担用户、认证、策略、票据、绑定、日志、外部接口编排。
* 安卓客户端：用于用户注册、登录、生物采集、终端环境采集、策略执行、应用访问。
* 证书/USB 认证模块：复用或对接 `ldap-cert-system`，提供证书签发、证书查询、挑战签名验证能力。
* 信任评估模型：对接 `UEBA4.2`，提供用户行为、设备行为、访问行为异常检测和风险等级输出。
* 声纹模型：对接 `voiceprint-engine`，提供声纹注册、特征提取、比对认证。
* 外部模拟系统：后量子属性系统、动态生物特征系统、广域低功耗系统、异构跨域系统、业务应用系统。

### 2. 核心演示链路

* 管理员查看用户并从后量子系统更新属性。
* 用户使用 USB 认证模块/PIN 登录，并访问模拟应用。
* 管理员绑定用户与终端后，绑定终端可登录，未绑定终端被拒绝。
* 管理员绑定用户与动态生物特征后，动态生物不匹配时拒绝登录。
* 管理员绑定用户与物联网设备后，用户、终端、设备关系不一致时拒绝登录。
* 用户在人机物系统 A 登录后，访问系统 B 应用时无需重复登录。
* 用户通过异构跨域服务访问外部系统 C 应用。

## 三、预设技术栈

### 1. 前端管理端与网页客户端

* 框架：Vue 3 + TypeScript + Vite。
* UI：Element Plus。
* 状态管理：Pinia。
* 路由：Vue Router。
* HTTP：Axios，统一封装请求、响应、错误码、Token 刷新。
* 图表：ECharts，用于信任评估、终端风险、认证流水统计。
* 构建工具：npm。
* 默认端口：`3002`。
* 主要页面：登录页、用户管理、注册审核、证书管理、生物特征审核、设备管理、绑定管理、认证策略编排、应用资源管理、日志审计、信任评估记录、系统配置。

### 2. 服务端

* 语言与框架：Java 21 + Spring Boot 3。
* 构建：Maven。
* Web：Spring Web。
* 安全：Spring Security + JWT。
* 数据访问：MyBatis-Plus。
* 数据库：MySQL 8，生产可替换 PostgreSQL；规划阶段按 MySQL 8 实现。
* 缓存：Redis，用于挑战码、登录会话、票据状态、临时随机码、短期策略缓存。
* 网关/反向代理：Nginx，用于统一入口、静态资源代理、后端转发、模型服务转发。
* API 文档：Springdoc OpenAPI。
* 日志：Logback + JSON 日志格式；关键审计日志入库。
* 默认端口：`8080`。

### 3. 安卓客户端

* 语言：Kotlin 优先，兼容 Java。
* 架构：MVVM。
* 网络：Retrofit + OkHttp。
* 本地存储：Room + DataStore。
* 任务调度：WorkManager，用于定时终端状态采集和策略同步。
* 生物能力：Android BiometricPrompt、CameraX、AudioRecord。
* 证书与密钥：Android Keystore。
* 终端信息采集：系统 API + 应用级事件采集；受 Android 权限限制的项目使用可控模拟数据。
* 策略执行：本地策略库 + 服务端策略同步。

### 4. 证书与 USB 认证

* 现有模块：`ldap-cert-system`。
* 技术：Flask + OpenSSL + LDAP + Docker Compose。
* 默认服务端口：`5000`。
* 能力：用户证书签发、证书入 LDAP、证书查询、挑战码下发、签名验签。
* 集成方式：服务端通过 REST 调用证书模块，统一封装为 `CertificateService` 和 `UsbAuthService`。
* 生产替代方案：后续可替换为国密密码设备、USB Key SDK、CA/RA 系统接口。

### 5. 声纹模型

* 现有模块：`voiceprint-engine`。
* 技术：Python + FastAPI + ONNX Runtime。
* 默认端口：`5003`。
* 模型：`wespeaker_zh_cnceleb_resnet34.onnx`。
* 输入规格：16kHz、mono、PCM16/WAV。
* 能力：健康检查、声纹 embedding、声纹比对、阈值配置。
* 集成方式：服务端通过 REST 调用声纹服务；安卓端采集音频后上传服务端，由服务端转发模型或直接调用模型接口。

### 6. 信任评估模型

* 现有模块：`UEBA4.2`。
* 技术：Python + Flask + scikit-learn + pandas + joblib。
* 默认端口：`5004`。
* 算法：现有说明包含 Isolation Forest，当前 API 服务包含增量 OCSVM 模型调用能力；实现规划中以现有模型服务接口为准，服务端不重写算法。
* 能力：用户级异常检测、事件级异常检测、综合风险评估。
* 输入：登录、设备、文件、HTTP、邮件、终端环境、访问请求等行为数据。
* 输出：异常分数、风险等级、是否异常、摘要、事件级异常明细。

### 7. 部署与运行

* 开发环境：macOS/Linux，JDK 21，Node.js LTS，Python 3.10+，Docker。
* 容器化：优先为 MySQL、Redis、LDAP、证书模块、模型服务提供 Docker Compose；前后端本地运行。
* 生产形态：Nginx 统一入口，前端静态部署，后端 Spring Boot 独立服务，模型服务独立进程或容器。
* 端口规划：前端 `3002`，后端 `8080`，证书模块 `5000`，声纹 `5003`，UEBA `5004`，Redis `6379`，MySQL `3306`。

## 四、总体架构设计

### 1. 分层架构

* 表现层：前端管理端、网页客户端、安卓客户端。
* API 层：Spring Boot REST API，统一鉴权、参数校验、错误码和审计。
* 业务层：用户、证书、生物、设备、绑定、策略、认证、票据、信任评估、日志、外部系统适配。
* 数据层：MySQL 持久化业务数据，Redis 缓存挑战码、会话、票据状态和随机码。
* 模型与外部服务层：证书模块、声纹模型、UEBA 模型、后量子系统、动态生物系统、广域低功耗系统、异构互认系统。

### 2. 后端模块划分

* `auth`：管理员登录、用户登录、JWT、权限校验。
* `identity`：用户、设备、物体、实体身份注册与管理。
* `certificate`：证书签发、证书绑定、证书吊销、USB 挑战认证。
* `biometric`：指纹、人脸、声纹、动态生物特征注册、审核和认证结果管理。
* `device`：终端、物联网设备、摄像头、感知节点管理。
* `binding`：用户与终端、动态生物、物联网设备、应用资源绑定。
* `policy`：认证协议编配、信任阈值、安全基线、策略下发。
* `ticket`：身份票据签发、验证、刷新、保活、失效。
* `sso`：业务应用单点登录、跨人机物系统免登录。
* `trust`：终端环境接收、UEBA 调用、评估结果入库、访问决策。
* `integration`：外部系统适配器。
* `audit`：审计日志、认证流水、策略日志、模型日志。

### 3. 前端模块划分

* 登录与权限：管理员登录、Token 管理、路由权限。
* 用户管理：用户列表、详情、注册审核、属性更新、离线导入。
* 生物与证书：生物审核、模板状态、证书签发、吊销、绑定记录。
* 设备与绑定：终端管理、物联网设备管理、绑定关系维护。
* 策略编排：认证方式配置、场景策略、安全等级、信任阈值、策略下发。
* 应用资源：模拟应用列表、应用安全等级、访问入口。
* 日志审计：登录日志、认证流水、证书审计、绑定日志、SSO 日志、跨域日志、评估日志。
* 仪表盘：用户数、设备数、认证成功率、异常风险、策略执行情况。

## 五、关键数据模型规划

### 1. 身份与用户

* `sys_admin`：管理员账号、密码摘要、角色、状态、最后登录时间。
* `user_account`：用户账号、用户名、姓名、手机号、邮箱、证件号、状态、注册来源。
* `user_profile`：用户属性、部门、岗位、外部属性 JSON、更新时间。
* `registration_request`：注册申请、审核状态、审核人、审核时间、驳回原因。

### 2. 证书与生物特征

* `user_certificate`：证书序列号、指纹、证书内容、状态、签发时间、吊销时间。
* `biometric_template`：用户、类型、模板摘要、模型来源、审核状态、撤销状态、版本。
* `biometric_auth_record`：认证类型、请求参数摘要、比对结果、分数、阈值、失败原因。

### 3. 设备、物体与绑定

* `device_entity`：设备/物体 ID、类型、名称、标识、证书/密钥标识、状态、来源。
* `terminal_info`：终端 ID、设备指纹、系统版本、客户端版本、绑定状态。
* `iot_device_status`：物联网设备接入状态、最后上报时间、状态摘要。
* `binding_relation`：主体类型、主体 ID、目标类型、目标 ID、绑定状态、生效时间、失效时间。

### 4. 策略与应用

* `app_resource`：应用/功能 ID、名称、类型、安全等级、状态。
* `auth_method`：认证方式编码、名称、比对模式、是否启用。
* `auth_policy`：场景、应用、用户范围、设备范围、认证组合、调用顺序、信任阈值、会话有效期。
* `security_baseline`：终端类型、基线规则、风险等级、处置动作。
* `policy_publish_record`：策略版本、下发对象、下发时间、执行结果。

### 5. 认证、票据与审计

* `auth_session`：会话 ID、用户、终端、认证状态、当前步骤、过期时间。
* `identity_ticket`：票据 ID、用户、信任等级、签名摘要、签发时间、过期时间、状态。
* `ticket_verify_record`：票据验证方、验证结果、失败原因、应用 ID、时间。
* `sso_record`：来源系统、目标系统、应用、用户、结果、时间。
* `audit_log`：操作者、操作类型、业务对象、结果、IP、时间、详情 JSON。

### 6. 信任评估

* `terminal_event`：终端状态、软件状态、硬件状态、用户操作、外设事件、关键数据读写。
* `trust_assessment_request`：主体、终端、应用、输入摘要、模型版本、请求时间。
* `trust_assessment_result`：信任分值、信任等级、异常指标、告警、拒绝原因、模型返回原文。

## 六、接口设计原则

### 1. 通用规范

* API 前缀：`/api/v1`。
* 返回结构：`code`、`message`、`data`、`traceId`。
* 认证方式：管理端使用 JWT；模型与外部系统调用使用服务凭证或接口签名。
* 时间格式：ISO 8601 或统一 `yyyy-MM-dd HH:mm:ss`。
* 敏感字段：证件号、手机号、证书、模板摘要、模型输入需脱敏展示。
* 幂等性：注册上报、属性更新、策略下发、外部系统回调需支持幂等键。

### 2. 核心接口组

* 用户管理：注册、审核、列表、详情、属性更新、离线导入。
* 证书管理：签发、绑定、吊销、查询、挑战请求、挑战验证。
* 生物特征：提交、审核、撤销、声纹比对、动态生物结果同步。
* 设备管理：新增、编辑、启停、状态上报、详情查询。
* 绑定管理：绑定、解绑、绑定关系查询、绑定校验。
* 策略管理：认证策略 CRUD、策略发布、策略拉取、策略执行回执。
* 认证流程：认证协商、认证提交、二次认证、认证状态查询。
* 票据服务：签发、验证、刷新、失效。
* 信任评估：终端数据上报、评估请求、评估结果查询。
* SSO 与跨域：应用票据验证、跨系统互认、异构跨域访问请求。
* 日志审计：分页查询、详情、导出。

## 七、分阶段实施规划

### 阶段 0：工程初始化与基础规范

目标：建立可持续开发的工程骨架和运行环境。

实现内容：

* 创建 `backend` Spring Boot 工程，配置 Maven、Java 21、Spring Web、Spring Security、MyBatis-Plus、MySQL、Redis、OpenAPI。
* 创建 `frontend` Vue 3 + TypeScript + Vite 工程，配置 Element Plus、Pinia、Vue Router、Axios。
* 规划安卓客户端工程结构，确定包名、权限清单、网络配置、本地存储方案。
* 准备 Docker Compose：MySQL、Redis、Nginx、LDAP/证书模块、UEBA、voiceprint。
* 建立统一编码规范、接口错误码、日志格式、数据库命名规范。
* 建立基础数据字典：用户状态、设备类型、认证方式、认证结果、信任等级、策略场景。
* 输出第一版数据库迁移脚本。

交付物：

* 可启动的前端、后端基础工程。
* 基础环境启动说明。
* 数据库初始化脚本。
* 接口规范和错误码文档。

验收标准：

* 前端 `3002` 可访问。
* 后端 `8080` 健康检查可访问。
* 后端可连接 MySQL、Redis。
* OpenAPI 页面可查看基础接口。

### 阶段 1：用户、管理员、权限与基础审计

目标：实现管理端可登录、可管理用户、可记录审计。

实现内容：

* 管理员登录、JWT 签发、Token 校验、退出登录。
* 管理端路由权限与菜单权限。
* 用户列表、用户详情、用户基础信息更新。
* 用户注册申请、审核通过、审核驳回、审核记录。
* 离线新增用户、批量导入用户基础信息。
* 基础审计日志记录：管理员登录、用户新增、用户修改、注册审核。
* 前端实现用户管理、注册审核、审计日志基础页面。

交付物：

* 管理员登录模块。
* 用户管理模块。
* 注册审核模块。
* 基础审计日志模块。

验收标准：

* 管理员可登录并进入管理端。
* 用户信息可新增、查看、修改。
* 注册申请可审核并记录结果。
* 审计日志可查询。

### 阶段 2：后量子属性系统对接与用户属性更新

目标：满足测试方案“用户管理”链路。

实现内容：

* 增加外部系统适配器 `PostQuantumAttributeClient`。
* 设计后量子属性系统模拟接口：按用户标识返回部门、岗位、属性集合、更新时间。
* 管理端增加“获取/更新用户属性”操作。
* 服务端保存外部属性原文和规范化属性字段。
* 记录属性更新审计日志和外部接口调用日志。
* 前端用户详情展示属性更新前后结果。

交付物：

* 后量子属性系统模拟服务或适配器。
* 用户属性更新接口。
* 用户属性展示与审计记录。

验收标准：

* 前置条件：后量子系统已有用户 A 属性。
* 管理端可查看用户 A 原始信息。
* 点击属性获取后，服务端调用后量子接口。
* 再次查看用户 A，属性信息已变化。

### 阶段 3：证书、USB 认证模块与基础登录

目标：实现 USB 认证模块/PIN 登录主链路。

实现内容：

* 对接 `ldap-cert-system`：证书签发、证书查询、挑战码请求、签名验证。
* 服务端封装证书模块接口，不让前端直接调用证书服务。
* 用户证书签发、证书绑定、证书吊销、证书审计。
* 网页客户端 USB 登录流程：用户输入账号/PIN，服务端发起挑战，证书模块完成验签。
* 安卓客户端保存证书、发起登录、提交认证信息。
* Redis 保存挑战码、过期时间、认证临时状态。
* 登录成功后创建认证会话。
* 登录失败记录失败原因。

交付物：

* 证书管理页面。
* USB 认证登录接口。
* 网页客户端登录页。
* 证书审计日志。

验收标准：

* 用户 A 插入 USB 认证模块并输入 PIN 后可登录。
* PIN 错误、证书无效、挑战过期时拒绝登录。
* 登录成功和失败均有日志。

### 阶段 4：应用资源、身份票据与单点登录

目标：实现登录后访问应用、票据签发、票据验证和 SSO。

实现内容：

* 应用资源管理：名称、编码、安全等级、状态、访问地址。
* 身份票据签发：用户标识、终端标识、信任等级、有效期、签名。
* 票据验证：真实性、有效期、签名、状态、信任等级。
* 票据刷新、保活、主动失效。
* 模拟业务应用系统，调用本系统票据验证接口。
* 前端实现应用访问入口。
* 后端记录票据签发、票据验证、应用访问日志。
* 初步支持系统 A 到系统 B 的票据互认，先用同一后端多租户/多系统标识模拟。

交付物：

* 应用资源管理。
* 身份票据服务。
* 单点登录验证接口。
* 模拟应用访问页面。

验收标准：

* 用户 A 登录后可访问某应用。

## 九、关键业务规则

### 1. 登录决策规则

* 用户账号必须存在且状态正常。
* 认证方式必须符合当前策略。
* USB/证书认证必须验证挑战签名成功。
* 若用户已绑定终端，则登录终端必须匹配。
* 若用户已绑定动态生物特征，则动态生物认证结果必须通过。
* 若用户已绑定物联网设备，则设备状态和绑定关系必须满足策略。
* 信任评估结果低于策略阈值时，必须触发二次认证或拒绝访问。

### 2. 票据规则

* 票据由服务端私钥签发。
* 票据必须包含用户、签发系统、信任等级、有效期、签名。
* 票据验证必须检查真实性、有效期、状态、签名、信任等级。
* 票据仅允许在配置的系统和应用范围内使用。
* 票据失效、过期或信任等级不足时不得静默通过。

### 3. 绑定规则

* 绑定关系由管理员创建、变更和解除。
* 同一用户可绑定多个实体，但策略可限制某类实体只能绑定一个。
* 绑定变更必须记录操作者、时间、变更前后内容。
* 绑定校验失败时，认证或访问必须返回明确原因。

### 4. 外部系统规则

* 外部系统调用结果必须记录请求摘要和响应摘要。
* 外部系统不可用时，根据场景采取降级：登录强依赖场景默认拒绝，信息展示场景允许提示后继续。
* 外部系统上报需校验随机码、签名或服务凭证。

## 十、安全与合规设计

* 密码不明文存储，使用 BCrypt 或等价强哈希。
* 证书、私钥、模型模板、敏感属性不得明文暴露给前端。
* 挑战码一次性使用，并设置短有效期。
* JWT 设置短有效期和刷新机制。
* 管理端敏感操作保留 PIN 或二次鉴权能力。
* 所有认证失败、权限失败、绑定失败、票据失败必须审计。
* 文件上传限制类型、大小、存储位置和访问权限。
* 生物模板仅保存必要摘要或受保护模板，原始样本按策略限制留存。
* Nginx 配置请求体限制、超时、反向代理白名单和 HTTPS 预留。
* 模型服务仅允许后端访问，不直接暴露给公网前端。

## 十三、风险与处理策略

* USB 认证模块硬件接口不稳定：先以 `ldap-cert-system` 挑战签名流程模拟，后续替换真实 SDK。
* 安卓终端环境采集权限受限：真实可采集项与模拟项分开，演示场景使用可控模拟数据补齐。
* 声纹样本质量影响结果：限定输入格式，提供录音质量检查和阈值配置。
* UEBA 模型输入与业务数据不一致：建立服务端标准化适配层，不让业务表直接耦合模型字段。
* 跨系统互认缺少真实外部系统：先用系统标识和模拟应用实现完整协议，再替换真实接口。
* 策略编排过度复杂：第一版采用表单配置和顺序执行，后续再扩展拖拽式流程编排。
* 日志数据量增长：审计日志与终端事件分表或冷热分层预留，常用查询字段加索引。

## 十五、安卓客户端与网页客户端阶段 0-10 补充计划

本章节用于补充阶段 0 至阶段 10 中安卓客户端、网页客户端的实现计划。管理端仍属于 `frontend` 工程，网页客户端也放在 `frontend` 工程内，通过路由、布局和角色区分。

### 阶段 0：客户端工程初始化

* 接入 Retrofit、OkHttp、Room、DataStore、WorkManager。
* 建立统一接口响应、Token 保存、错误处理、日志输出。
* 预留证书存储、终端标识生成、生物采集、终端状态采集模块。

网页客户端：

* 在 `frontend` 中区分管理端路由与用户端路由。
* 建立用户端基础布局，包括登录页、应用列表页、访问结果页。

* 建立用户端状态管理：登录用户、身份票据、终端标识、当前应用。

交付标准：

* 安卓客户端可启动并访问后端健康检查接口。
* 网页客户端 `3002` 可访问，用户端和管理端路由可区分。

### 阶段 1：基础登录框架与用户信息展示

安卓客户端：

* 实现用户登录页面骨架，包含账号、密码或认证入口。
* 实现用户注册页面骨架，支持录入用户名、密码、姓名、手机号、邮箱、证件号。
* 实现注册记录、审核进度、审核结果展示页面。
* 实现用户基础信息展示页面。
* 登录成功后保存用户基础信息和认证状态。

网页客户端：

* 实现用户端登录页。
* 实现用户信息页，展示用户基础信息、属性信息、账号状态。
* 实现用户端注册申请页和审核进度查看页。
* 与管理端用户审核结果联动展示。

交付标准：

* 用户可在安卓或网页端提交注册申请。
* 用户可查看审核状态。
* 登录态、用户信息、错误提示可正常展示。

### 阶段 2：后量子属性更新结果展示

安卓客户端：

* 展示用户属性信息，包括部门、岗位、外部属性摘要、更新时间。
* 支持刷新用户信息，展示服务端最新属性。
* 不直接调用后量子系统，只调用本系统服务端接口。

网页客户端：

* 用户信息页展示后量子属性同步后的结果。
* 对属性为空、同步中、同步失败状态进行清晰提示。
* 用户端不提供属性更新操作，属性更新由管理端触发。

交付标准：

* 管理端触发属性更新后，安卓端和网页端刷新可看到新属性。

### 阶段 3：USB/证书登录与基础认证

安卓客户端：

* 实现数字证书保存与展示。
* 实现证书登录/辅助认证入口。
* 实现 USB 认证模块或证书挑战认证的客户端流程；真实 USB 能力不足时，先使用服务端模拟挑战认证。
* 登录请求需携带终端标识、客户端类型、客户端版本。
* 登录成功后保存身份票据、会话状态和用户信息。

网页客户端：

* 实现 USB 认证模块登录页。
* 用户输入账号/PIN 后，由服务端发起挑战认证流程。
* 登录成功后保存身份票据。
* 登录失败时展示明确失败原因，包括 PIN 错误、证书无效、挑战过期、账号异常。

交付标准：

* 用户 A 可通过网页客户端 USB/PIN 登录。
* 安卓客户端可完成证书/模拟 USB 登录。
* 登录成功后客户端持有身份票据。

### 阶段 4：应用访问、身份票据与单点登录

安卓客户端：

* 实现应用列表页，展示系统内置功能和模拟应用。
* 点击应用时携带身份票据请求访问。
* 展示访问成功、票据过期、信任等级不足、需重新认证等状态。
* 支持票据刷新或重新登录入口。

网页客户端：

* 实现用户端应用列表页。
* 实现应用访问跳转或访问结果页。
* 访问业务应用时携带身份票据，由业务应用或本系统验证票据。
* 支持单点登录状态展示。

交付标准：

* 登录后的用户可访问模拟应用。
* 票据无效或过期时，客户端能引导重新认证。

### 阶段 5：终端标识与终端绑定访问控制

安卓客户端：

* 生成并持久化终端标识。
* 每次登录和访问应用时携带终端标识。
* 展示当前终端绑定状态。
* 当服务端返回“终端未绑定”或“绑定不匹配”时，阻断访问并提示原因。

网页客户端：

* 为浏览器端生成终端标识，保存在本地存储。
* 登录和应用访问时携带终端标识。
* 展示终端绑定失败、终端状态异常等提示。
* 支持测试方案中的终端 1、终端 2 场景，可通过配置或本地标识切换模拟。

交付标准：

* 绑定前用户 A 可在终端 1、终端 2 登录访问。
* 管理端绑定用户 A 与终端 1 后，终端 1 可访问，终端 2 被拒绝。
* 客户端能展示拒绝原因。

### 阶段 6：策略拉取、认证编排执行与二次认证

安卓客户端：

* 支持拉取认证策略、采集监控策略、安全基线策略。
* 本地保存策略版本和策略内容。
* 根据服务端返回的认证步骤，引导用户依次完成认证。
* 支持二次认证页面，包括重新认证、关键因子认证、增强因子认证。
* 支持向服务端上报策略执行结果。

网页客户端：

* 用户访问应用时，根据服务端返回策略展示认证步骤。
* 支持多认证方式顺序执行的页面状态，例如 USB/PIN 后再执行绑定校验或二次认证。
* 支持策略变更后的提示和重新认证。
* 支持策略执行结果回执。

交付标准：

* 客户端可根据不同应用策略执行不同认证流程。
* 触发二次认证时，客户端能完成引导并提交结果。

### 阶段 7：声纹与生物特征采集认证

安卓客户端：

* 实现声纹录音采集入口，推荐 16kHz、mono、PCM16/WAV。
* 支持上传声纹注册样本。
* 支持上传声纹验证样本并展示认证结果。
* 支持指纹本地认证入口，优先使用 Android BiometricPrompt。
* 支持人脸采集入口，第一版可上传照片或短视频片段，由服务端或模型侧处理。
* 展示生物特征审核状态、撤销状态、重新采集要求。

网页客户端：

* 支持声纹音频文件上传或浏览器录音，作为声纹注册/验证输入。
* 支持生物认证结果展示。
* 用户端仅提交和查看自己的生物特征状态，不提供审核能力。

交付标准：

* 用户可提交声纹样本。
* 用户可发起声纹认证并看到通过/失败、分数或失败原因。
* 安卓端可完成本地指纹认证入口接入。

### 阶段 8：动态生物特征绑定认证

安卓客户端：

* 展示用户是否已绑定动态生物特征。
* 登录或访问时接收服务端返回的动态生物校验要求。
* 与动态生物系统的交互由服务端完成，安卓端负责展示等待、成功、失败状态。
* 动态生物不匹配时阻断登录或访问，并展示原因。

网页客户端：

* 展示动态生物绑定状态。
* 登录或访问时展示动态生物校验过程和结果。
* 支持测试方案中“用户 B 使用用户 A 的 USB 模块/PIN 但步态不符”的失败展示。

交付标准：

* 用户 A 动态生物识别通过后可继续 USB/PIN 登录。
* 用户 B 动态生物不符时，客户端展示无法登录原因。

### 阶段 9：物联网设备绑定访问

安卓客户端：

* 展示用户绑定的物联网设备信息和当前接入状态。
* 登录或访问时携带终端标识，由服务端校验物联网设备绑定关系。
* 接收并展示设备未接入、设备异常、绑定不一致等错误。
* 支持终端 1 模拟物联网设备接入状态展示。

网页客户端：

* 展示用户绑定物联网设备与接入状态。
* 支持用户访问应用时触发物联网设备状态校验。
* 支持测试方案中用户 A 成功、用户 B 因设备绑定不一致失败的展示。

交付标准：

* 用户 A 在绑定设备接入正常时可登录访问。
* 用户 B 在设备绑定不一致时无法登录或无法访问。

### 阶段 10：终端信任监控与 UEBA 结果展示

安卓客户端：

* 实现终端状态采集，包括系统版本、客户端版本、软件状态、硬件状态、外设连接、关键操作事件等。
* 支持定时采集和事件触发采集。
* 上报前进行基础清理、分类和字段标准化。
* 接收服务端返回的信任评估结果，包括信任分值、信任等级、风险告警、处置动作。
* 展示当前终端安全状态和策略执行情况。
* 当信任等级不足时，引导二次认证或阻断访问。

网页客户端：

* 采集浏览器端可获得的终端信息，包括浏览器、操作系统、IP 相关信息、客户端版本、本地终端标识。
* 支持模拟终端环境异常事件上报，用于联调 UEBA 和访问决策。
* 展示当前信任等级、访问风险和处置结果。
* 当服务端返回风险阻断或二次认证要求时，展示对应流程。

交付标准：

* 安卓端可持续上报终端环境数据。
* 网页端可上报基础终端信息和模拟异常事件。
* 客户端可展示 UEBA 评估结果。
* 信任等级不足时，客户端能触发二次认证或阻断访问。

### 阶段 0-10 客户端补齐优先级

若服务端已经完成阶段 8，而客户端尚未实现，应按以下顺序补齐：

1. 网页客户端登录、应用访问、票据保存。
2. 管理端用户、设备、绑定、策略、生物、动态生物页面。
3. 网页客户端终端标识、终端绑定失败展示。
4. 网页客户端动态生物和物联网绑定结果展示。
5. 安卓客户端基础工程、登录、证书保存、终端标识。
6. 安卓客户端声纹采集、策略拉取、二次认证。
7. 安卓客户端终端环境采集和 UEBA 结果展示。

该顺序优先保证测试方案可通过，再补齐安卓端完整体验。
