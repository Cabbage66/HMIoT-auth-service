# 阶段9：联调稳定性与验收（实施计划与实现结果）

## 一、实施计划

### 1. 目标

完成前端上线前联调加固，补齐稳定性能力与可观测性能力，并提供可执行的联调验收入口，确保管理端与网页端关键流程可验证、可定位问题。

### 2. 实施范围

- 全局 HTTP 稳定性增强：
  - GET 请求失败重试（网络异常/5xx，最多2次，指数退避）
  - 401 会话失效统一清理与跳转（管理员/用户分别处理）
  - API 运行日志采集（方法、URL、状态码、耗时、traceId、消息）
- 新增阶段9“联调验收台”：
  - 页面：`/admin/go-live`
  - 一键执行验收项：用户、凭据、生物、设备绑定、策略、信任、审计聚合
  - 验收结果可视化（状态/耗时/错误信息）
  - 运行日志查看与清空
- 导航补齐：
  - 管理端核心页面侧边栏增加“联调验收”入口

### 3. 验收标准

- 构建通过；
- 联调验收台可执行并输出通过/失败结果；
- 异常请求可在运行日志中定位，并保留 traceId 信息；
- Token 失效场景可自动回到对应登录页。
