# 阶段4：终端与绑定管理（实施计划与实现结果）

## 一、实施计划

### 1. 目标

实现管理端“设备实体管理 + 终端管理 + 绑定关系管理”完整功能，覆盖新增、编辑、状态变更、绑定与解绑操作，满足后续认证策略和访问控制联动前置要求。

### 2. 实施范围

- 页面：新增 `/admin/device-binding`。
- 设备实体管理：
  - 列表查询、分页、创建、编辑、启用/禁用。
  - 接口：`/api/v1/devices`、`/api/v1/devices/{id}`、`/api/v1/devices/{id}/status`。
- 终端管理：
  - 列表查询、分页、创建、编辑、启用/禁用。
  - 接口：`/api/v1/terminals`、`/api/v1/terminals/{id}`、`/api/v1/terminals/{id}/status`。
- 绑定关系管理：
  - 绑定关系查询、用户-终端绑定、用户-动态生物绑定、解绑。
  - 接口：`/api/v1/bindings`、`/api/v1/bindings/user-terminal`、`/api/v1/bindings/user-dynamic-biometric`、`/api/v1/bindings/{id}/unbind`。
- 统一风格：
  - 延续前端风格规范（渐变头部、侧栏、工具栏、卡片、表格分页）。

### 3. 验收标准

- 三个子模块均可完整执行 CRUD/状态/绑定动作并回显结果。
- 关键动作具备输入校验和错误提示。
- 构建通过，路由与菜单入口可稳定访问。

### 2. 功能完成度

- 设备实体管理：
  - 列表查询（关键字/类型/状态）+ 分页。
  - 新增设备、编辑设备。
  - 设备启用/禁用状态变更。
- 终端管理：
  - 列表查询（关键字/客户端类型/状态）+ 分页。
  - 新增终端、编辑终端。
  - 终端启用/禁用状态变更。
- 绑定关系管理：
  - 绑定关系列表查询（主体/目标/关系类型/状态）+ 分页。
  - 用户-终端绑定。
  - 用户-动态生物绑定。
  - 绑定解绑（支持输入解绑原因）。

### 3. 风格与交互

- 页面风格沿用既定后台风格系统：渐变头部、侧栏导航、工具栏筛选、卡片分区、表格分页。
- 关键动作均具备前端交互与提示：输入校验、成功提示、失败提示、确认输入。
- 与阶段1-3已有会话与路由守卫体系兼容。
