# 阶段 7：声纹与生物特征管理实施计划

## Context

阶段 6 已完成认证方式、认证策略、安全基线、策略发布/回执，以及登录和票据访问流程中的策略执行接入。阶段 7 的目标是在现有认证编排基础上，把“声纹”从阶段 6 中的未接入强因子升级为可真实注册、审核、验证、审计和留痕的生物认证能力，并补齐生物模板全生命周期管理。

用户要求继续按完整上线标准实现阶段 7，不为了速度牺牲完整性；仍以后端能力优先。现项目不是 git 仓库，不能使用 git worktree。worktree 本身不会显著节省模型 token，它主要节省人工切换分支/隔离改动的成本；真正影响 token 的是我们读取多少文件、输出多少内容。建议每完成一个阶段就测试，而不是最后集中测试，否则跨阶段问题会叠加且定位成本高。当前没有前端时，阶段验收以后端自动化测试、启动后端、curl/Postman/Swagger 接口调用、数据库记录和审计记录核验为主。

## 现有基础与约束

- 不修改 `voiceprint-engine`、`UEBA4.2`、`ldap-cert-system`；如发现 `voiceprint-engine` 接口无法满足后端上线能力，先说明原因再确认是否改外部模块。
- 复用已有配置：`backend/src/main/resources/application.yml` 中 `hmiot.integrations.voiceprint-service-url`，默认 `http://localhost:5003`。
- 复用现有表，不随意改 V1 基线；字段确实不足时新增迁移并保留详细 SQL 注释。
- V1 已有阶段 7 核心表：
  - `biometric_template`：用户、类型、模板摘要、模板引用、模型来源、模型版本、阈值、审核状态、模板状态、版本、提交/审核/吊销信息、metadata。
  - `biometric_auth_record`：用户、类型、模板、requestId、分数、阈值、认证结果、失败原因、模型来源、原始响应。
- 复用现有实现模式：
  - 外部服务调用：`module/integration/service/CertificateIntegrationClient.java`
  - 外部调用留痕：`module/integration/service/ExternalIntegrationCallService.java`
  - 审计：`module/audit/service/AuditLogService.java`
  - 管理端/用户端安全上下文：`common/security/CurrentAdmin.java`、`common/security/CurrentUser.java`
  - 分页：`module/user/vo/PageVO.java`
  - 管理端权限：`common/security/SecurityConfig.java`
  - 策略执行：`module/policy/service/PolicyExecutionService.java`

能力：

- `enroll(username/userId, audioBase64, metadata)` 或等价 embedding/注册调用：返回模板引用、模板摘要/embedding 摘要、模型来源、模型版本、阈值、原始响应摘要。
- `verify(templateRef/templateDigest, audioBase64, threshold, metadata)`：返回是否通过、score、threshold、failReason、requestId、模型版本、原始响应摘要。

实现边界：

- 若 `voiceprint-service-url` 是 `mock://...`，提供本地开发 mock：固定可预测摘要、score 和通过/失败规则，便于自动测试。
- 若是 HTTP(S)，使用 `RestClient` 调用真实 `voiceprint-engine`；响应缺少关键字段时抛出明确 `BusinessException`。
- 所有注册、验证和健康检查失败都通过 `ExternalIntegrationCallService` 记录 `VOICEPRINT_HEALTH`、`VOICEPRINT_ENROLL`、`VOICEPRINT_VERIFY`。

### 4. 用户声纹提交与模板生命周期

用户端接口：

- `POST /api/v1/voiceprints/enroll`：当前登录用户提交声纹样本，后端调用声纹服务提取/注册特征，写入 `biometric_template`，默认 `biometric_type=VOICEPRINT`、`audit_status=PENDING`、`template_status=ACTIVE`。
- `POST /api/v1/voiceprints/recollect`：当前登录用户重新采集；旧有效模板可标记为 `REPLACED` 或保留历史，新模板版本号递增并进入待审核。
- `GET /api/v1/voiceprints/me`：当前用户查看自己的声纹模板状态和最近审核/撤销信息，不返回原始模板内容。

管理端接口：

- `GET /api/v1/biometric-templates`：分页查询，支持用户、类型、审核状态、模板状态。
- `GET /api/v1/biometric-templates/{id}`：详情。
- `POST /api/v1/biometric-templates/{id}/review`：审核通过/拒绝，记录审核人、审核时间、拒绝原因。
- `POST /api/v1/biometric-templates/{id}/revoke`：撤销模板，记录撤销时间和原因。

校验规则：

- 用户必须存在且未删除，用户端接口只能操作当前用户自己的模板。
- 只允许 `VOICEPRINT` 在阶段 7 真实接入；指纹、人脸只保留数据结构，不伪造认证通过。
- 待审核模板不能用于正式认证。
- 已撤销模板不能认证、不能再次审核通过。
- 同一用户可保留历史版本，但认证只选最新审核通过且未撤销的活跃模板。

审计操作：

- 用户：`VOICEPRINT_ENROLL`、`VOICEPRINT_RECOLLECT`
- 管理员：`BIOMETRIC_TEMPLATE_REVIEW`、`BIOMETRIC_TEMPLATE_REVOKE`

### 5. 声纹认证与流水记录

用户端接口：

- `POST /api/v1/voiceprints/verify`：当前登录用户上传待验证音频，后端选择该用户最新审核通过声纹模板，调用声纹服务比对，并写入 `biometric_auth_record`。
- `GET /api/v1/voiceprints/auth-records/me`：当前用户查看自己的声纹认证记录。

管理端接口：

- `GET /api/v1/biometric-auth-records`：分页查询认证流水，支持用户、类型、结果、时间范围。
- `GET /api/v1/biometric-auth-records/{id}`：详情。

记录要求：

- 成功/失败都写入 `biometric_auth_record`，保存 score、threshold、auth_result、fail_reason、model_source、raw_response。
- 声纹服务异常时也写入失败流水和外部集成失败记录。
- 响应给客户端只返回必要结果：通过/拒绝、score、threshold、failReason、recordId，不返回原始模板或完整原始响应。

### 6. 接入策略执行，让 VOICEPRINT 成为已实现认证因子

更新 `PolicyExecutionService` 的已接入认证方式判断：

- 阶段 7 后 `VOICEPRINT` 不再返回“认证方式暂未接入当前阶段”。
- 对 `APP_ACCESS` 或 `STEP_UP_AUTH` 策略中包含 `VOICEPRINT` 的情况，要求客户端先完成 `/api/v1/voiceprints/verify` 并在后续票据/访问请求中提供可校验的声纹认证上下文。

若现有票据请求结构不足以携带“本次声纹验证记录 ID/结果”，优先新增最小必要字段到票据签发 DTO，并在 `IdentityTicketService` 中校验：

- 记录属于当前用户。
- 类型为 `VOICEPRINT`。
- 结果为 `SUCCESS`。
- 记录创建时间在策略允许的短时间窗口内。

不把“存在历史成功声纹记录”当成永久通过，避免强因子被长期复用。

### 7. 权限与安全配置

更新 `SecurityConfig`：

- 管理端：`/api/v1/biometric-templates/**`、`/api/v1/biometric-auth-records/**` 仅 `SYSTEM_ADMIN` 或 `ADMIN`。
- 用户端：`/api/v1/voiceprints/**` 需要用户认证。

安全要求：

- 不保存原始音频文件到数据库；请求中音频只用于调用模型，模板表仅保存模板摘要/引用和模型元数据。
- 接口限制请求字段必填和音频大小/格式元数据；如果 Spring multipart 配置不适配，先用 JSON base64 版本完成后端能力，并为 Android 上传预留 multipart 扩展。
- 所有失败返回明确原因，但不泄露模板摘要、模型内部原始字段或敏感音频内容。

## 验证方案

阶段 7 完成后立即验证，不等后续阶段：

1. 运行自动化测试：`./backend/mvnw -f backend/pom.xml clean test`。
2. 启动后端，使用 Swagger/curl/Postman 进行后端接口验收：
   - 用户提交声纹样本，生成 `PENDING` 模板。
   - 管理员分页查询模板并审核通过。
   - 用户上传验证音频，返回通过/拒绝、score、threshold，并写入认证流水。
   - 管理员查看认证流水和模板详情。
   - 管理员撤销模板后，用户再次声纹验证被拒绝。
   - 声纹服务失败时，外部集成调用记录、认证失败流水和审计日志均存在。
   - 配置含 `VOICEPRINT` 的策略后，访问/票据签发能识别声纹因子；未提供近期成功声纹记录时拒绝。
3. 如果本地未启动真实 `voiceprint-engine`，将 `VOICEPRINT_SERVICE_URL` 临时设为 `mock://voiceprint` 验证后端链路；真实联调时再切回 `http://localhost:5003`。
