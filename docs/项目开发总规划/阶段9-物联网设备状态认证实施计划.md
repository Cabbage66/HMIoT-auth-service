# 阶段 9：物联网设备状态认证实施计划

## Context

阶段 9 实现物联网设备状态认证：把终端关联设备实体的在线状态、可信状态、外部 LPWAN/IoT 查询结果和设备上报结果纳入登录、票据签发与访问策略决策，确保只有处于在线且可信状态的已启用设备能作为认证上下文参与登录和应用访问。

本阶段继续以后端工程级完整实现为准；当前没有前端，验收通过接口、数据库记录、审计记录、外部调用记录和自动化测试完成。项目当前不是 git 仓库，不使用 git worktree。优先复用 V1 已有 `iot_device_status` 表和现有设备/终端模型；外部 IoT/LPWAN 系统使用 `hmiot.integrations.lpwan-service-url`，默认 `mock://lpwan` 完成本地闭环。

## 实施范围

- 复用 `device_entity`、`terminal_info.device_entity_id`、`iot_device_status`、`external_integration_call`、`audit_log`。
- 新增 IoT 设备状态查询、主动刷新、外部回传、当前用户校验接口。
- 新增 IoT/LPWAN 外部系统适配器，支持 `mock://lpwan` 和 HTTP(S)。
- 将 `IOT_DEVICE` 接入登录策略、票据签发/复用与访问策略。
- 用户响应和票据载荷只暴露状态摘要，不返回 `lastPayload` 或外部原始响应。

## 接口能力

- `GET /api/v1/iot-device-statuses/health`：管理端检查 IoT/LPWAN 服务健康状态。
- `GET /api/v1/iot-device-statuses`：管理端分页查询设备状态。
- `GET /api/v1/devices/{deviceEntityId}/iot-status`：管理端查看单设备状态。
- `POST /api/v1/devices/{deviceEntityId}/iot-status/query`：管理端主动刷新设备状态。
- `POST /api/v1/iot-device-statuses/reports`：外部 IoT/LPWAN 系统状态回传。
- `POST /api/v1/iot-device-statuses/check`：当前用户校验当前终端关联设备状态。

## 核心规则

- 上报或查询前必须确认 `device_entity` 存在、未删除且状态为 `ENABLED`。
- `connectStatus` 只接受 `ONLINE`、`OFFLINE`、`UNKNOWN`。
- `trustStatus` 只接受 `TRUSTED`、`UNTRUSTED`、`SUSPECT`、`UNKNOWN`。
- 同一 `deviceEntityId` 使用 `iot_device_status` 唯一记录，重复上报执行更新。
- 登录和票据访问中的设备状态认证只能使用当前终端关联设备的最新状态。
- 设备状态必须为 `ONLINE/TRUSTED`，且 `lastReportAt` 必须在 300 秒有效窗口内。
- `IOT_DEVICE` 是上下文/设备状态因子，不替代 `USB_LOGIN`、`CERTIFICATE_LOGIN` 等主认证方式。

## 验证方案

1. 运行 `./backend/mvnw -f backend/pom.xml clean test`。
2. 在 `LPWAN_SERVICE_URL=mock://lpwan` 下验证设备状态上报、主动查询、当前用户校验、登录策略和票据访问策略。
3. 检查 `iot_device_status`、`external_integration_call`、`audit_log` 是否记录完整。
4. 确认用户响应和票据 payload 不包含 `lastPayload` 或外部原始响应。
