# 阶段 5：设备实体管理与终端绑定访问控制实施计划

## Context

阶段 4 已完成应用资源、身份票据、票据验证、票据生命周期、SSO 与模拟业务应用访问链路。阶段 5 的目标是补齐“设备实体管理与终端绑定访问控制”能力，使认证成功后的用户身份不再只依赖用户证书/USB/PIN 与票据，还必须结合业务终端、设备状态和用户-终端绑定关系进行约束，满足项目规划中“公用密码身份认证与终端绑定”的验收链路。

本阶段只实现阶段 5 范围：设备/物体实体管理、终端信息维护、用户与终端绑定/解绑、绑定校验服务，以及认证、票据签发和 SSO 访问流程中的终端绑定校验。不进入阶段 6 的策略引擎完整配置、动态信任持续评估、风险模型深度联动或前端页面实现。现有 `ldap-cert-system`、`UEBA4.2`、`voiceprint-engine` 不改动；如需设备合法性和绑定状态，优先在本后端通过已有数据库表与服务适配完成。

## 已确认的现有基础

- V1 基线 SQL 已包含 `device_entity`、`terminal_info`、`iot_device_status`、`binding_relation`。
- `auth_session` 和 `identity_ticket` 已包含 `terminal_id`，但当前流程尚未完整使用可信终端上下文。
- `CertificateLoginService` 是接入终端识别和登录绑定校验的核心位置。
- `IdentityTicketService`、`SsoService` 是接入访问流程绑定校验的核心位置。
- `AuditLogService` 已支持管理员、用户和系统审计，可复用记录设备管理、绑定管理和绑定校验失败原因。

- `module/device/entity/DeviceEntity.java`
- `module/device/entity/TerminalInfo.java`
- `module/device/entity/IotDeviceStatus.java`
- `module/device/mapper/DeviceEntityMapper.java`
- `module/device/mapper/TerminalInfoMapper.java`
- `module/device/mapper/IotDeviceStatusMapper.java`
- `module/device/dto/**`
- `module/device/vo/**`
- `module/device/service/DeviceEntityService.java`
- `module/device/service/TerminalInfoService.java`
- `module/device/controller/DeviceEntityController.java`
- `module/device/controller/TerminalInfoController.java`

管理端接口：

- `GET /api/v1/devices`：分页查询设备/物体实体，支持关键字、设备类型、状态、来源系统。
- `GET /api/v1/devices/{id}`：设备详情。
- `POST /api/v1/devices`：新增设备实体。
- `PUT /api/v1/devices/{id}`：更新设备名称、类型、指纹、证书主体、来源系统、描述、元数据。
- `POST /api/v1/devices/{id}/status`：启用/禁用设备实体。
- `GET /api/v1/terminals`：分页查询终端，支持关键字、客户端类型、状态、设备关联。
- `GET /api/v1/terminals/{id}`：终端详情。
- `POST /api/v1/terminals`：管理员维护终端信息。
- `PUT /api/v1/terminals/{id}`：更新终端客户端信息、设备关联、状态、元数据。
- `POST /api/v1/terminals/{id}/status`：启用/禁用终端。

### 2. 绑定关系模块

新增绑定模块，映射 `binding_relation` 表：

- `module/binding/entity/BindingRelation.java`
- `module/binding/mapper/BindingRelationMapper.java`
- `module/binding/dto/**`
- `module/binding/vo/BindingRelationVO.java`
- `module/binding/service/BindingRelationService.java`
- `module/binding/service/TerminalBindingValidationService.java`
- `module/binding/controller/BindingRelationController.java`

管理端接口：

- `GET /api/v1/bindings`：分页查询绑定关系。
- `POST /api/v1/bindings/user-terminal`：绑定用户与终端。
- `POST /api/v1/bindings/{id}/unbind`：解绑指定绑定关系。
- `GET /api/v1/users/{userId}/terminals`：查询用户已绑定终端。
- `GET /api/v1/terminals/{terminalId}/users`：查询终端绑定用户。

绑定规则：用户没有 active `LOGIN_TERMINAL` 绑定时允许合法启用终端登录和访问；用户存在 active `LOGIN_TERMINAL` 绑定时，仅允许绑定终端登录和访问。绑定校验失败必须返回明确错误并记录审计原因。

### 3. 认证流程接入终端识别与绑定校验

扩展 `CertificateChallengeRequest`、`CertificateVerifyRequest`，补充 `terminalCode`、`deviceFingerprint`、`clientType`、`clientVersion`、`osName`、`osVersion`、`userAgent` 等终端字段。

改造 `CertificateLoginService`：

- 挑战阶段按 `terminalCode` 登记或更新 `terminal_info`。
- 创建 `AuthSession` 时写入 `terminalId`，并在 `authContext` 保存终端摘要。
- 验证阶段使用会话中的可信终端，不信任 verify 请求切换终端。
- 签发用户 JWT 前执行用户-终端绑定校验。
- JWT claims 增加 `terminalId`、`terminalCode`、`clientType`。
- 绑定校验失败时，不签发 JWT，认证会话标记失败并记录审计。

### 4. 当前用户上下文扩展

- `CurrentUser` 增加 `terminalId`、`terminalCode`、`clientType`。
- `JwtAuthenticationFilter` 从用户 JWT claims 读取终端信息并写入 `CurrentUser`。
- 管理员 `CurrentAdmin` 保持不变。

### 5. 票据与 SSO 接入绑定校验

改造 `IdentityTicketService`：

- 签发票据前执行终端绑定校验。
- 票据 `terminalId` 使用 `CurrentUser.terminalId()`，不信任客户端任意传入。
- 若请求 `terminalId` 与当前登录终端不一致，直接拒绝。
- 票据载荷增加 `terminalId`、`terminalCode`、`clientType`。
- 复用、刷新、保活票据时校验当前终端与票据终端一致，并重新执行绑定约束。

改造 `SsoService`：

- `access(...)` 在签发或复用票据前执行当前用户终端绑定校验。
- SSO 记录详情中写入终端信息和失败原因。

### 6. 安全与审计

更新 `SecurityConfig`：

- `/api/v1/devices/**`、`/api/v1/terminals/**`、`/api/v1/bindings/**` 仅允许 `SYSTEM_ADMIN` 或 `ADMIN`。
- `/api/v1/auth/**` 继续公开，但服务层校验终端合法性和绑定关系。
- 票据签发、刷新、保活、SSO access 继续要求用户认证，并校验终端上下文。

审计覆盖设备/终端新增、更新、启停，用户终端绑定/解绑，登录与访问阶段的终端绑定校验失败。

## 验收标准

1. 管理员可维护设备、终端和用户-终端绑定关系。
2. 绑定前，用户 A 可在终端 1、终端 2 使用 USB/证书登录并访问应用。
3. 管理员绑定用户 A 与终端 1 后，终端 1 可登录、签发票据并访问应用。
4. 用户 A 在终端 2 使用 USB/证书登录时被拒绝。
5. 已登录旧终端在解绑或禁用后，继续签发票据、SSO access、票据刷新/保活均被拒绝。
6. 拒绝原因可在审计日志中查看。
7. 后端测试通过：`./backend/mvnw -f backend/pom.xml test`。

## 不做内容

- 不实现阶段 6 的完整策略引擎、策略下发和动态风险闭环。
- 不修改 `ldap-cert-system`、`UEBA4.2`、`voiceprint-engine`。
- 不把真实生产密钥、生产设备指纹规则或生产系统地址写死在仓库。
- 不让客户端请求中的 `terminalId` 绕过当前登录上下文。
- 不让绑定校验失败静默通过。
- 不让用户 token 访问设备、终端、绑定管理接口。
- 不重写已确认的总规划和需求文档。
