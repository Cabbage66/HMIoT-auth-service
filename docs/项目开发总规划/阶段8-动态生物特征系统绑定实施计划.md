# 阶段 8：动态生物特征系统绑定实施计划

## Context

阶段 7 已完成声纹模板、声纹验证、认证流水、策略与票据中 `VOICEPRINT` 强因子接入，并通过后端测试。阶段 8 的目标是实现“动态生物特征系统绑定”链路：管理员可把用户与外部动态生物特征标识（以步态为主）绑定，外部动态生物系统可主动回传或由后端主动查询识别结果，登录/票据/访问策略可把动态生物匹配结果纳入认证决策，且所有绑定、外部调用、匹配结果都可审计和留痕。

本阶段仍以后端工程级完整实现为准；当前没有前端时，通过后端接口、数据库记录、审计记录、外部调用记录和自动化测试完成验收。项目当前不是 git 仓库，不使用 git worktree。外部动态生物系统优先通过 `mock://dynamic-biometric` 完成本地闭环；不修改外部模块，除非真实联调发现接口能力缺失并经用户确认。

## 现有基础与约束

- 复用 `backend/src/main/resources/application.yml` 中 `hmiot.integrations.dynamic-biometric-url`，默认 `mock://dynamic-biometric`。
- 复用 V1 已有表，优先不新增迁移：
  - `binding_relation`：保存用户与动态生物外部标识的绑定关系。
  - `biometric_template`：可保存动态生物特征引用/摘要/模型元数据。
  - `biometric_auth_record`：保存动态生物认证流水。
  - `external_integration_call`：保存外部动态生物系统调用记录。
  - `audit_log`：保存管理员绑定/解绑和用户认证操作审计。
- 如果实现中发现现有表无法表达必要字段，再新增迁移；新增 SQL 必须包含详细字段注释。
- 普通用户接口不能返回模板摘要、外部原始响应、模型内部细节等敏感信息。
- 动态生物匹配不能被“历史任意成功记录”永久复用；只允许使用短时间窗口内、属于当前用户且匹配外部标识的成功记录。

## 推荐实施方案

### 1. 保存阶段 8 项目计划文档

新增：

- `docs/项目开发总规划/阶段8-动态生物特征系统绑定实施计划.md`

内容以本计划为准，作为阶段 8 的可追溯实施计划；不重写已完成的阶段 7 计划和总规划文档。

### 2. 扩展动态生物绑定能力

复用并扩展现有绑定模块：

- `backend/src/main/java/com/hmiot/hmiot_backend/module/binding/service/BindingRelationService.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/binding/controller/BindingRelationController.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/binding/dto/**`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/binding/vo/**`

新增或扩展能力：

- 管理端绑定用户与动态生物特征标识：`POST /api/v1/bindings/user-dynamic-biometric`。
- 管理端查询某用户动态生物绑定：`GET /api/v1/users/{userId}/dynamic-biometrics`。
- 管理端按外部动态生物标识反查绑定用户：`GET /api/v1/dynamic-biometrics/{externalSubjectId}/users`。
- 继续复用现有 `POST /api/v1/bindings/{id}/unbind` 完成解绑。

绑定语义：

- `subject_type=USER`
- `subject_id=userId`
- `target_type=DYNAMIC_BIOMETRIC`
- `target_id` 使用外部标识的稳定正数哈希，不保存原始敏感特征。
- `relation_type=DYNAMIC_BIOMETRIC_ID`
- `status=ACTIVE/INACTIVE`

校验规则：

- 用户必须存在且未删除。
- 同一用户同一动态生物类型只允许一个当前有效绑定，重复绑定明确拒绝。
- 解绑后不再允许该外部动态生物标识参与认证决策。

审计操作：

- `USER_DYNAMIC_BIOMETRIC_BIND`
- `USER_DYNAMIC_BIOMETRIC_UNBIND`

### 3. 新增动态生物外部系统适配器

新增：

- `backend/src/main/java/com/hmiot/hmiot_backend/module/integration/service/DynamicBiometricIntegrationClient.java`

能力：

- `health()`：检查动态生物系统可用性。
- `queryMatch(userId, externalSubjectId, biometricType, requestId)`：服务端主动查询用户当前动态生物识别结果。
- `normalizeReport(...)`：统一处理外部系统主动回传的动态生物识别结果。
- `targetSystem()`：返回当前集成目标，用于外部调用留痕。

实现边界：

- `mock://dynamic-biometric`：提供本地 mock，按请求字段可预测返回通过/失败。
- HTTP(S)：使用 `RestClient` 调用真实外部服务；缺少 requestId、matched、score、threshold 等关键字段时抛出明确业务异常。
- 所有健康检查、主动查询、回传处理异常都通过 `ExternalIntegrationCallService` 记录。

### 4. 新增动态生物认证服务与接口

新增或扩展 biometric 模块：

- `backend/src/main/java/com/hmiot/hmiot_backend/module/biometric/service/DynamicBiometricAuthService.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/biometric/controller/DynamicBiometricController.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/biometric/dto/DynamicBiometricQueryRequest.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/biometric/dto/DynamicBiometricReportRequest.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/biometric/vo/DynamicBiometricVerifyResponse.java`
- `backend/src/main/java/com/hmiot/hmiot_backend/module/biometric/vo/DynamicBiometricHealthResponse.java`

用户/系统接口：

- `GET /api/v1/dynamic-biometrics/health`：健康检查。
- `POST /api/v1/dynamic-biometrics/query`：当前登录用户发起服务端主动查询动态生物匹配结果。
- `POST /api/v1/dynamic-biometrics/reports`：外部动态生物系统主动回传识别结果。
- `GET /api/v1/dynamic-biometrics/auth-records/me`：当前用户查看自己的动态生物认证记录。

记录要求：

- 成功/失败都写入 `biometric_auth_record`，`biometric_type=DYNAMIC_BIOMETRIC`，保存 requestId、score、threshold、authResult、failReason、modelSource、rawResponse。
- 外部系统异常或绑定不存在时，也写失败流水；不能只抛异常不留痕。
- 用户响应只返回通过/拒绝、score、threshold、failReason、recordId、requestId，不返回 rawResponse。

### 5. 接入登录流程动态生物校验

- 在 USB/PIN 登录请求 DTO 中新增 `dynamicBiometricAuthRecordId`。
- 登录成功前校验该动态生物认证记录属于当前登录用户、类型正确、结果成功、未过期，且外部动态生物标识与用户当前有效绑定一致。
- 用户 B 即使持有用户 A 的 USB/PIN，只要动态生物记录不属于用户 B 或绑定不匹配，就必须拒绝登录。

### 6. 接入策略与票据访问决策

- 将 `DYNAMIC_BIOMETRIC` 标记为阶段 8 已实现认证方式。
- 在 `TicketIssueRequest` 中新增 `dynamicBiometricAuthRecordId`，保留 `voiceprintAuthRecordId`。
- 在 `IdentityTicketService` 中新增动态生物近期成功记录校验。
- 票据 payload 只写入认证记录 ID 和认证时间，不写入外部原始响应或敏感特征。

### 7. 权限与安全配置

- 管理端绑定接口继续使用 `/api/v1/bindings/**` 的管理员权限。
- `/api/v1/dynamic-biometrics/query` 和 `/api/v1/dynamic-biometrics/auth-records/me` 需要用户认证。
- `/api/v1/dynamic-biometrics/reports` 作为阶段 8 外部 mock/联调回调入口开放；真实生产接入前需补齐外部签名/共享密钥校验。
- `/api/v1/dynamic-biometrics/health` 默认需要认证。

### 8. 更新测试与启动验证

更新上下文测试依赖，确保 Spring Boot context 可启动，并运行 Maven 测试。

## 验证方案

1. 运行自动化测试：`./backend/mvnw -f backend/pom.xml clean test`。
2. 启动后端，在 `DYNAMIC_BIOMETRIC_URL=mock://dynamic-biometric` 下用 Swagger/curl/Postman 验证绑定、查询、回传、登录拒绝/通过、票据策略校验。
3. 检查 `binding_relation`、`biometric_auth_record`、`external_integration_call`、`audit_log` 的记录完整性。
