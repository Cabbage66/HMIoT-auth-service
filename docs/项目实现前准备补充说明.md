# 项目实现前准备补充说明

## 一、当前结论

当前准备工作已经可以支撑 AI 开始实现具体项目代码。

已经具备的基础：

* 项目需求已确定：`docs/项目需求-整理版.md`。
* 测试方案已确定：`docs/测试方案_回忆版.md`。
* 总体开发规划已确定：`docs/项目开发总规划/项目开发总规划.md`。
* 后端项目已创建：`backend`，Java 21 + Spring Boot 3。
* 前端项目已创建：`frontend`，Vue + TypeScript + Vite。
* 基线数据库 SQL 已创建：`backend/src/main/resources/db/migration/V1__baseline_schema.sql`。
* 现有模型/外部模块已存在：`UEBA4.2`、`voiceprint-engine`、`ldap-cert-system`。

但如果直接让 AI 全量实现，仍容易出现依赖混乱、目录风格不统一、接口前后不一致、外部系统边界不清的问题。因此建议先补齐工程约束，再按阶段指挥 AI 实现。

## 二、后续 docs 文件放置约定

后续新增说明文件直接放在 `docs` 目录下，不再新建子目录。

已有子目录可以暂时保留，不影响开发：

* `docs/项目开发总规划/`
* `docs/数据库设计/`
* `docs/方案图片/`

后续若需要整理文档结构，可统一迁移；当前不建议在开发前做无关移动，避免图片引用和路径引用失效。

## 三、开始编码前建议补齐的内容

### 1. 后端依赖需要统一

当前 `backend/pom.xml` 同时包含：

* `spring-boot-starter-data-jpa`
* `mybatis-spring-boot-starter`

项目规划中选择的是 MyBatis/MyBatis-Plus。建议正式实现时：

* 删除 JPA 依赖，避免实体、Repository、事务风格混杂。
* 使用 MyBatis-Plus 或 MyBatis 二选一。推荐 MyBatis-Plus，减少基础 CRUD 工作量。
* 增加 MySQL 驱动、Redis、Flyway、JWT、OpenAPI 等依赖。

建议依赖方向：

* `spring-boot-starter-web`
* `spring-boot-starter-security`
* `spring-boot-starter-validation`
* `spring-boot-starter-data-redis`
* `mysql-connector-j`
* `mybatis-plus-spring-boot3-starter`
* `flyway-core`
* `flyway-mysql`
* `springdoc-openapi-starter-webmvc-ui`
* `jjwt-api`、`jjwt-impl`、`jjwt-jackson`
* `lombok`

### 2. 后端配置文件需要补齐

当前 `application.properties` 只有应用名。正式编码前应补充：

* 服务端口：`8080`。
* MySQL 连接。
* Redis 连接。
* Flyway 开关和迁移目录。
* MyBatis/MyBatis-Plus 配置。
* JWT 密钥、过期时间。
* 外部服务地址：证书模块、声纹模型、UEBA、后量子模拟、动态生物模拟、广域低功耗模拟、异构跨域模拟。
* 文件上传大小限制。
* 日志级别。

建议使用：

* `application.yml` 作为主配置。
* `application-dev.yml` 作为本地开发配置。
* 真实密钥不要写死在仓库，先用开发默认值，后续改环境变量。

### 3. 初始数据需要补齐

`V1__baseline_schema.sql` 已包含认证方式和模拟应用资源，但还缺少开发启动所需基础数据。

建议新增 `V2__seed_initial_data.sql`：

* 默认管理员账号。
* 默认认证策略。
* 默认安全基线。
* 用户 A、用户 B 的演示账号。
* 终端 1、终端 2 的演示终端记录。
* 广域低功耗演示设备。
* 系统 A、系统 B、系统 C 的模拟系统标识。

注意：管理员密码必须存 BCrypt 摘要，不存明文。

### 4. 外部系统模拟边界需要明确

测试方案依赖多个“其他系统”。若先不做模拟服务，后端主流程会卡住。

建议第一版统一在 `backend` 内部做 mock adapter，后续再拆独立服务：

* 后量子属性系统：按用户 ID 返回部门、岗位、属性版本。
* 动态生物系统：按用户 ID 返回步态识别是否通过。
* 广域低功耗系统：按设备 ID 返回设备接入状态。
* 异构跨域系统：按票据和目标系统返回互认结果。

证书、声纹、UEBA 已有独立目录，可以真实 HTTP 对接；如果启动成本高，也应先提供 mock fallback。

### 5. API 契约需要先定第一版

正式让 AI 写前后端前，建议先让 AI 生成一版接口清单，包括：

* 请求路径。
* 请求方法。
* 请求参数。
* 响应结构。
* 错误码。
* 对应页面或业务流程。

优先接口：

* 管理员登录。
* 用户列表/详情/属性更新。
* 注册审核。
* 证书签发/吊销。
* 设备管理。
* 绑定管理。
* USB 登录。
* 应用访问。
* 票据验证。
* 信任评估记录。
* 跨域访问。

### 7. 阶段顺序需要严格控制

不建议一次指挥 AI 实现所有模块。应按可验收链路推进：

1. 后端基础依赖、配置、数据库迁移、统一响应、异常处理。
2. 管理员登录、JWT、安全配置。
3. 用户管理和后量子属性更新。
4. 设备管理和绑定管理。
5. USB/证书登录主流程。
6. 应用资源、票据、SSO。
7. 动态生物绑定。
8. 物联网设备绑定。
9. 信任评估与 UEBA。
10. 声纹模型接入。
11. 跨系统和跨域访问。
12. 前端页面补齐和联调。

每一步都应要求 AI：

* 只实现当前阶段。
* 给出变更文件清单。
* 启动或运行测试。
* 不改无关模块。
* 不重写已确认文档。

## 五、是否可以开始指挥 AI

可以开始，但第一条指令不应是“实现整个系统”。

推荐第一条编码指令：

> 请先整理后端工程基础设施：将后端依赖统一为 Spring Boot 3 + Java 21 + MyBatis-Plus + MySQL + Redis + Flyway + JWT + OpenAPI；删除不使用的 JPA 依赖；补齐 `application.yml` 和 `application-dev.yml`；接入 Flyway 并确保 `V1__baseline_schema.sql` 可被识别；实现统一响应、全局异常、基础安全配置骨架。不要实现业务模块。

第二条编码指令：

> 在已有基础设施上实现管理员登录、JWT 鉴权、用户管理、用户属性更新 mock adapter 和审计日志，满足测试方案中的“用户管理”场景。只实现该阶段，不做 USB、绑定、SSO。

这样推进最稳。

## 六、当前不建议做的事

* 不建议一次性生成所有 Controller、Service、Mapper，否则大量代码未联调，后期返工成本高。
* 不建议先做复杂可视化认证编排，第一版用表单配置即可。
* 不建议先做真实安卓终端采集，先用模拟终端数据跑通服务端决策。
* 不建议把所有外部系统都做成独立服务，第一版可以在后端做 mock adapter。
* 不建议现在迁移已存在的 docs 子目录，避免破坏已有图片和文档路径。
